## 2026-10-04 · 射击小游戏「霓虹打击 Neon Strike」（`/shoot`，和快艇、赛车同一套 $BOAT）

- 玩法：竖屏俯视的霓虹几何射击（参考操作者给的「游戏汁水 12 招」视频，抽帧在 `arm/ops/.tmp/game-frames/`）。飞船自动连射（每秒约 9 发，伤害 18～26，15% 暴击 ×2.5，连击 ≥ 15 双管），手机按住任意位置相对拖动，电脑鼠标跟随或方向键 / WASD；**碰到敌人或敌弹一下就结束**（操作者定的）。敌人：粉色方块（60 血 5 分）、橙色六边形（200 血 15 分，20 秒起开火）、绿色精英（1200 血 100 分，头顶血条，40 秒起，扇形弹）。编队入场 → 悬停摇摆 → 俯冲撞人，悬停越来越短、俯冲越来越快，60 秒起「弹雨」，100 秒后小方块也开火。连击：上次击杀后 2.2 秒内再杀 +1，每 10 连击倍率 +0.5，最高 ×3。
- 计分防作弊：敌人只在「已放出的敌人基础分合计 ≤ `spawnBudget(游戏秒数)`」时才放（40 + 15·s + 0.125·s²，两分钟后每秒 45），所以分数 ≤ 3 × 预算。后端 `boat.ts` 的 `shootBudget` 用同一公式，按开局到结束的墙钟秒数截断（顿帧时游戏时间停走，游戏秒数 ≤ 墙钟，不会误截）。**两边公式要一起改**。奖励 `floor(min(分数 / 10, 300) × rate)`（操作者定：每 10 分 1 枚，单局最多 300，越往后越难）。自动驾驶约 55 秒到 3000 分，70～110 秒阵亡。
- 后端（已部署 indexer）：`GAMES` 加 `shoot`，分数存在 `boat_runs.meters`；`boatRunEnd` 按这局的 game 选上限，快艇 / 赛车还是 `MAX_MPS`；射击局不更新 `boat_players.best`（游戏页把它显示成「最佳 X 米」）；`/info` 的 `rules.shootPointsPerBoat = 10`。临时脚本 `web/scripts/_shoot-api.mjs` 用一次性钱包在线上测过（截断、奖励、best、三款合计局数、排行榜分开），这个测试钱包 10.4 在射击榜上有 262 分、赛车榜 26 米。
- 画面（`shoot/gfx.ts`）：three.js 正交相机 + 自写的即时模式三角批 `Batch`（每个顶点 RGBA + uv，uv = (-2,-2) 是实心，[-1,1] 是软圆点），描边、填充、拖尾、粒子、冲击环都走它，普通混合和加法各一批，共两个 draw call。网格是 shader，最多 8 个冲击波会把网格线推开。发光是 `UnrealBloomPass`（`outputColorSpace` 设成线性，开不开发光颜色一致）。伤害飘字、分数、连击画在上面一层 2D canvas，跟震屏一起抖。
- 打击感 12 项（`shoot/fx.ts`，只影响画面和声音，不改计分）：闪白（受击纯白 2 帧）、击退（沿子弹方向的弹簧偏移 + 旋转）、挤压拉伸（按屏幕横竖轴压扁回弹；入场拉长、落位压扁；飞船开火后坐）、伤害飘字（弹出放大 → 上飘 → 淡出，暴击 34px 橙红带「!」）、粒子（命中火花 + 碎屑，击杀碎片 + 火花 + 闪光）、顿帧（命中 40 ms、暴击 60 ms，两次命中顿帧至少隔 0.25 s；击杀 65、暴击击杀 90、精英 160 ms，每次都顿）、震屏（trauma²，按伤害加，每秒衰减 1.7）、冲击波（白环 + 网格扭曲，精英双环）、拖尾火光（子弹拖尾、枪口火焰、尾焰）、发光（Bloom + 光晕）、音效（`shoot/audio.ts` 全合成：开枪、命中、暴击、击杀按连击升半音最多两个八度、倍率升级琶音、断连、死亡）、连击分数（大号斜体「连击 xN」+ 倒计时条 + 倍率，断连提示，分数滚动，击杀 +分）。
- 调试：`?fx=1` 左上角出 12 个开关（线上也能用，只影响画面），`?fx=0` 全关进入，`?fx=flash,shake` 只开这几项，键盘 1～9、0、-、= 依次切换。只在 localhost 生效：`?demo=1` 自动玩，`?capture=1` 停掉时钟、用 `window.__shoot.step(n)` 逐帧走（另有 `info()` / `fx(k, on)` / `audio(t0, 秒)`），`?t=60` 从 60 秒的难度开始，`?lab=1` 靶场（三个靶子站着不动、打掉 0.8 秒重生、飞船不会死，`&aim=110` 让飞船对准某个 x）。最佳分数 `arm-shoot-best`，静音 `arm-shoot-muted`。
- 自查材料（未跟踪）：`arm/ops/.tmp/shoot-video/neon-strike-fx.mp4`（540×960 60 fps，先全关 6 秒再全开 9 秒，带原声，`web/scripts/_shoot-video.mjs` 录的）；逐项对比图脚本 `_shoot-lab.mjs` / `_shoot-fx.mjs`（输出在 `scripts/.shots/lab`、`scripts/.shots/fx`）。Edge 和 Chromium 99 都跑过整局。已部署网页。

## 2026-10-03 · 赛车小游戏「极速跨海 Bridge Rush」（`/race`，和快艇同一套 $BOAT）

- 玩法和快艇一样：三车道跑酷，车固定在 z=0，世界向 +z 流，同样的 `speedAt` / `METRE`（0.25），所以后端 13 m/s 的上限照用。← → / 点左右半屏换道，↑ / 空格 / 上滑弹跳。障碍：同向车流（10 世界单位/秒，不能跳）、锥桶（撞了只减速 28%，锥桶飞出去）、路障 / 木箱（跳得过去，撞了结束）、跳台（自动起飞，能飞过车）。200 米起有车打转向灯变道（变道前检查不会把三条道都堵死），150 米起「逆行卡车」（照快艇炮击：红色箭头铺在那条道上 + 喇叭，T 秒后到达，2.6 → 1.8 s；375 米起两条道），逆行车撞到前面的车会一起炸掉。静态障碍比车流快，后生成的障碍会追上前面的车，生成时按相遇点预判，保证至少留一条道（`hazardLanesOk`）。「擦肩而过」：车贴着过去或你 0.8 秒内刚从它那条道让开，只是特效，不加分。
- 画面：跨海悬索桥（`race/scene.ts`，塔、主缆、吊索、桥墩、路灯都按一个滚动偏移排布，不用生成）+ 快艇的水面 shader（`boat/water.ts` 原样复用，颜色换成黄昏）+ 快艇的海岛棕榈（`boat/engine.ts` 导出了 `buildIsland` / `loadPalms`）。从黄昏开到深夜（`TimeOfDay`：天空 / 水 / 雾 / 灯光按跑出的距离插值，约 430 米入夜；路灯、缆索灯串、尾灯、警灯、逆行车大灯都是一个 Points 发光层 `Sprites`），太阳阴影跟车走，环境贴图（PMREM）随天色每 0.05 重算一次。声音全部合成（`race/audio.ts`：换挡引擎、风噪、轮胎、喇叭、爆炸）。
- 模型：Kenney Car Kit（CC0，`public/race/*.glb` + `Textures/colormap.png`，授权 `License-kenney.txt`），按 1.6 倍放大、转成朝 −z。开始界面可换 4 辆车（存 `localStorage arm-race-car`），最佳 `arm-race-best`，静音 `arm-race-muted`。
- 后端（已部署 indexer）：`boat_runs` 加了 `game` 列（默认 `boat`，`ensure()` 里 `alter table … add column if not exists`）；`POST /api/boat/run` 带 `{game:"race"}`，`GET /api/boat/board?game=race`。余额、门票、奖励规则、**每天 10 局计分是两款游戏合计**。游戏探索页加了赛车卡片、排行榜切「快艇 / 赛车」。已部署网页。
- 本地调试（只在 localhost 生效）：`?d=1000` 从 1000 世界单位开始（分数从起点算）、`?tod=0.8` 固定天色、`?todRate=2` 加快入夜、`?car=race-future`、`?demo=1` 自动驾驶、`?capture=1` 停掉时钟，脚本用 `window.__race.step(n)` 一帧一帧走（1/60 s），`__race.audio(t0, 秒)` 把这段时间的声音离线渲染成 WAV（音效调用按游戏时间记下来再用 OfflineAudioContext 重放，和画面严格对齐）。
- 宣传视频：`arm/ops/.tmp/race-video/arm-bridge-rush.mp4`（1920×1080 60 fps，约 39 秒，游戏原声 + `publisher/bgm/614.mp3` 垫乐，结尾卡片 `slide.html`）。录法：本地生产构建 + `next start`，跑临时脚本 `web/scripts/_race-video.mjs`（无头 Edge 走显卡，每帧截图；自动驾驶撞得太早就重录）→ `_race-slide.mjs` → ffmpeg 合成（命令见 `race-video/finish.ps1`）。

## 当前正在排查的问题：视频通话概率性无画面

已搭好完整的日志上报链路，等待复现后取日志分析：

1. **客户端上报**：两端 `CallManager` 的 `clog()` 在本地打印之余，把日志（带毫秒时间戳）缓冲、每 3 秒批量 POST `/call/log`（`{callId, platform, lines[]}`），挂断时立即冲刷。callId 在发起/收到邀请时绑定（`bindLogCall`）。
2. **后端**：表 `call_client_log`（`CallClientLog`），接口 `POST /call/log`（仅通话参与方可写，单批 ≤500 行）。
3. **管理后台 → 「通话日志」模块**：通话记录列表（双方、状态、时长、日志批数）→ 查看 → **下载日志**（双端合并为一个 txt）。

**操作流程**：用两台手机复现一次"无画面"的视频通话 → 管理后台 → 通话日志 → 找到那通电话 → 下载 txt → 发给 AI 分析。日志里重点看 WHIP/WHEP exchange 结果、onTrack 是否触发、renderer 绑定。

**根因已定位**（2026-08-15，通过帧级统计日志对比 `dca71899…` 一通）：
- 现象：Android 拉流 `bytesRecv=0`（音视频都是 0），但 ICE CONNECTED、onTrack 也触发；iOS 推流 framesEncoded 正常增长。
- 原因：**SRS 接受"发布者尚未推流"时的 WHEP 订阅**（返回合法 SDP、ICE 能通），但发布者随后才推流时，这个早到的订阅者永远收不到 RTP。双方 accept 后并行建流，谁的订阅先于对方的推流完成，谁就黑屏/无声——这就是"概率性"的来源（Android 建流通常比 iOS 快，iOS 要等前台+音频会话+摄像头）。
- 修复（主方案，信令保证时序）：新增 `POST /call/:callId/published` + WS 事件 `published`——每端 WHIP 推流成功后通知对方，对方**收到 published 才开始 WHEP 订阅**（10 秒超时兜底直接订阅）。后端已部署。
- 修复（兜底）：两端 `CallManager` 保留**拉流零流量看门狗**——订阅完成 4 秒后 inbound-rtp 仍 0 字节则重新 WHEP 订阅（最多 4 次），日志 `pull NO media, resubscribe #n` / `pull media flowing`。**需重编两端验证**。

帧级日志（保留，排查任何通话问题都有用）：
- 每 5 秒 RTP 统计：push 端 framesEncoded/bytesSent，pull 端 framesReceived/framesDecoded/bytesReceived。
- 摄像头采集：iOS `capture started WxH@fps`（fps 已按格式上限收敛）；Android CameraEventsHandler（打开/出首帧/错误/冻结）。
- 渲染器首帧：两端 `renderer[remote/local]` 首帧与分辨率回调。
