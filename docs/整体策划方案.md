# 地陪系统 整体策划方案

版本：v1.0（2026-08-11）
状态：待确认

---

## 一、产品定位与风格

**平台定位：以一对一聊天 / 语音 / 视频为底座的社交平台。**"地陪"只是平台上的第一个业务模块，后期会陆续对接游戏等更多模块。架构与排版从第一天起按"平台 + 可插拔模块"设计：

- **平台核心层（不随模块变化）**：账号体系、IM 聊天、音视频通话、积分钱包、礼物、广场、定位。所有模块共用同一套账号与积分。
- **业务模块层（可插拔）**：地陪（找地陪 + 约单/接单）为模块一；游戏为后续模块，通过统一的模块入口、统一钱包接口（扣分/加分走同一账本）、统一账号 token 接入，原生或 H5 形式均可。
- **模块入口后台可配**：后台维护模块列表（名称、图标、入口地址、排序、上下架、可见性别），客户端按配置动态渲染"大厅"页入口，上新模块不发版（H5 模块）或仅增量发版（原生模块）。

用户可浏览广场动态、进入地陪模块按城市找人/约单、一对一文字/语音/视频沟通、赠送礼物。

- 视觉风格：**黑金豪华风**。深色底（#0E0E12 / #16161D），香槟金点缀（#D4AF37 / #C9A063），卡片圆角 + 细金描边，衬线标题字体，克制的动效。
- 图标：全部使用矢量线性图标（自绘 SVG / iconfont），**禁止使用 emoji**。
- 三端（Web / Android / iOS）UI 与功能同步设计、同步开发，保持一致的视觉语言。

| iOS App | Swift + SwiftUI | 全功能（含语音/视频通话） |

## 三、功能模块

### 1. 账号体系（一机一号，无密码，BNB 链地址即账号）
- **无密码**。注册只填：昵称、年纪、头像；性别必选（男/女，注册后锁定，用于全局性别隔离）
- **账号自动生成**：服务端生成 BNB 链（BSC，secp256k1）密钥对，**地址（0x...）就是账号**；私钥经服务端主密钥 AES-256-GCM 加密托管落库，后期可支持导出/链上功能
- **一机一号**：设备 ID 与账号一一绑定，同一设备只能注册一个账号
- **卸载恢复**：App 启动时携带设备 ID 调用 `/auth/enter`——该设备已注册则直接恢复账号并下发 JWT；未注册则进入注册流程。卸载重装不丢号
- 设备 ID 来源：Android 用 ANDROID_ID（同签名重装不变）；iOS 用 Keychain 保存的 UUID（卸载后 Keychain 仍保留）；Web 用 localStorage UUID
- JWT 鉴权，三端统一
- 个人资料：昵称、头像、性别、年纪、城市、个性签名、相册（图片/视频）
- 地陪认证：提交资料 → 管理后台审核 → 获得地陪标识，出现在"找地陪"列表

### 2. IM 聊天（单聊 + 群聊）
- WebSocket 长连接（JSON 协议），支持：文本、图片、视频、礼物消息、通话邀请/挂断信令
- 会话列表（单聊/群聊混排）、未读数、离线消息（上线拉取）、历史消息分页
- **群聊**：
  - 创建群（创建者为群主）、邀请成员、申请加入、退群；群主可踢人、转让、解散
  - 群资料：群名、群头像、公告、成员列表（上限默认 500，后台可调）
  - 群消息类型与单聊一致（文本/图片/视频/礼物）；群内送礼指定接收成员
  - 未读数按成员记录（`last_read_msg_id`）；@成员 提醒
  - 群聊不受性别隔离限制（成员靠邀请/申请进入）
- Web 端同样支持文字/图片/视频消息，仅不支持语音视频通话
- **消息加密**：
  - 传输层：正式环境 WSS/HTTPS；测试期无证书，由应用层加密兜底
  - 应用层：消息内容按会话使用 **AES-256-GCM** 加密后传输与落库（单聊每会话一把密钥、群聊每群一把密钥，密钥均用服务端主密钥包裹存储），数据库中不存明文，运维直接查库看不到内容
  - 图片/视频消息加密其访问地址与缩略图元数据，媒体文件走带签名的临时 URL

### 3. 语音/视频通话（一对一，仅 App）
- 走 **SRS 推拉流**：每人推一路流到 SRS，拉对方一路流，组成 1v1
- 协议：**WebRTC（WHIP 推流 / WHEP 拉流）**，UDP 8000，低延迟；信令（邀请、接听、拒绝、挂断、超时）走 IM WebSocket
- 默认参数 **640x480 @ 30fps**，码率默认 800kbps
- **后端可调**：管理后台配置分辨率/帧率/码率，App 发起通话前从接口拉取生效参数
- 通话计时展示；通话记录落库

### 4. 礼物系统
- 礼物由管理后台配置：名称、图标（矢量/图片素材）、积分价格、上下架、排序
- 聊天中赠送 → 扣积分 → 对方收到礼物消息 + 收礼记录
- 收礼方积分入账（平台抽成比例后台可配，默认 0%，测试期直通）
- 初始礼物示例：玫瑰(1)、香槟(52)、跑车(520)、城堡(1314)、火箭(3344)

### 5. 货币系统（积分）
- **1 积分 = 1 元**，只保留整数积分
- **平台无充值功能**，积分来源仅两种：管理后台发放/调整、收礼入账
- 流水：后台发放、送礼支出、收礼收入、约单冻结/结算/退回、系统调整，全部落 `wallet_transaction` 账本表，余额由账本推导校验；钱包含 `balance`（可用）与 `frozen`（约单托管冻结）两个字段
- **无提现功能**，用户端只展示积分明细

### 6. 广场（动态）
- 发布：文字 + 最多 9 图 或 1 视频（上传至 MinIO，视频封面自动截取）
- 全国可见（仅异性可见，服务端过滤），可按城市筛选，可按"最新 / 附近"排序
- 点赞、评论
- 两种浏览模式，一键切换：
  - **普通模式**：双列瀑布流卡片
  - **抖音模式**：全屏竖向滑动，视频自动播放，右侧悬浮操作栏（头像/点赞/评论/礼物）
- 三端一致实现（Web 抖音模式用全屏滚动吸附）

### 7. 定位
- App：系统 GPS 授权 → 逆地理编码得到城市（先用行政区划表 + 经纬度就近匹配，避免依赖第三方 key；预留高德接口）
- Web：浏览器 Geolocation，拒绝时手动选择城市
- 城市数据：内置全国省市数据表
- 用途：广场"附近"排序、找地陪按城市筛选、资料页展示

### 8. 找地陪
- 列表/卡片浏览已认证地陪：头像、昵称、城市、距离、签名、相册预览（仅显示异性地陪）
- 筛选：城市；排序：最新、距离
- 进入详情 → 发起聊天 / 语音 / 视频（Web 端通话按钮弹下载引导）

### 9. 约单/接单（男发单、女接单）
- **男生端**：发布需求单，填写 时间、城市+地点、报酬（积分）、补充说明；发布时报酬积分**托管冻结**
- **女生端**：专属"接单大厅"界面，按城市筛选浏览订单，可报名接单
- 流程状态机：
  1. `待接单`：男生发布，报酬冻结，女生可报名（一单可多人报名）
  2. `进行中`：男生从报名者中选定一人确认，自动建立/打开双方会话
  3. `已完成`：男生确认完成 → 托管报酬转入女生积分（入 wallet_transaction 账本）
  4. `已取消`：确认前男生可取消（冻结退回）；进行中取消需双方协商，争议走后台仲裁
- 超时处理：到约定时间 48 小时后未确认完成，后台可介入仲裁
- 界面按性别区分：男生端显示"我的发单"入口，女生端显示"接单大厅 + 我的接单"入口
- 管理后台：订单列表、仲裁处理（判给任一方）

## 四、技术架构

### 后端（`houduan/`）
- **Node.js 20 + NestJS + TypeScript**（内存占用小，适配应用服务器仅 ~3.7G 可用内存的现状；WebSocket 原生友好；与 Web 前端同语言）
- MySQL 8（Prisma ORM）+ Redis 7（在线状态、验证码、缓存）+ MinIO（图片/视频对象存储）
- 模块分层：
  - 平台核心：auth、user、im(WebSocket 网关)、call(通话信令+参数)、gift、wallet、moment(广场)、geo(城市)、admin、upload、module(模块入口配置)
  - 业务模块：guide(地陪)、task(约单/接单)；后续 game 模块按同样方式挂载，统一走 wallet 账本扣分/加分
- 对游戏模块预留的统一接口：SSO token 校验、钱包变动（幂等流水）、模块入口配置下发
- REST API + `/ws` WebSocket，统一 JSON 返回 `{code, msg, data}`

### 流媒体
- **47.122.115.33 上已有现成 SRS 6.0.184**（源码安装，`/usr/local/src/srs/trunk`），直接使用、无需部署
- WebRTC 已开启且做过一对一低延迟调优（min_latency、gop_cache off、NACK）；HTTP API/WHIP/WHEP 走 1985/tcp，**媒体流走 7999/udp**，RTMP 1935/tcp
- 流命名：`live/{callId}_{userId}`，双方各推各拉
- 后端通过 SRS HTTP API 做流鉴权回调（on_publish/on_play 校验 token）与挂断清理

### 客户端
- Android：Kotlin、Compose、Retrofit/OkHttp（REST+WS）、ExoPlayer（广场视频）、WebRTC（google webrtc 库，WHIP/WHEP 对接 SRS）、CameraX
- iOS：Swift、SwiftUI、URLSession（REST+WS）、AVPlayer、WebRTC（Google WebRTC pod/SPM）
- Web：React 18 + Vite + TS，Zustand 状态，自绘黑金组件库；官网与管理后台独立入口同仓库

## 八、已确认决策

1. 后端选型：NestJS(Node)。API 无状态 + JWT，WebSocket 消息经 Redis Pub/Sub 跨节点路由，后期加节点只需扩容器 + nginx upstream，不改业务代码。
2. 账号体系：一机一号、无密码、BNB 链地址即账号、设备 ID 恢复（不接短信）。
3. App 名称定为「心之音」，图标与正式名称后续可换。
