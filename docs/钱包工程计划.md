# 钱包工程计划（第一版）

> 建于 2026-10-03。状态：**规划中，未开工**。开工、提交、花钱的链上操作都要操作者确认。
> 本文档不写任何私钥、助记词、密码、token。

## 1. 已定的决策

| 事项 | 决定 |
|---|---|
| 私钥 | 自托管：私钥只在用户设备上，平台不保存、不能动用。不复用心之音 `user.encPrivKey`（那是服务器托管的） |
| 技术路线 | **网页钱包 + 原生壳**：钱包界面和逻辑写在 Arm 网站（Next.js + viem），Android / iOS 只做一层 WebView 壳和小桥接 |
| 界面 | **Ave 只用来对字段和流程**（每页有哪些信息、按钮、步骤），视觉要比 Ave 好看，按 §5.1 的设计方向重新做；图标 / 插画 / Logo 用自己的（Phosphor），不拿 Ave 的素材和代码 |
| 平台顺序 | 先 Android（只在官网下载的安装包里启用），再 iOS 海外版 |
| iOS | 和国内版同一个 App；App Store 所在国家是中国（`SKStorefront.countryCode == "CHN"`）时彻底没有钱包入口 |
| 开关 | 默认关闭；后台「用户管理」按人打开，另有全局开关 |
| 苹果开发者账号 | 钱包上架要「组织」类型账号（审核规则 3.1.5），上架前再处理 |

## 2. 第一版范围

**做**

1. 钱包：创建 / 导入助记词、导入私钥、多钱包切换、备份校验、导出助记词 / 私钥、改密码、删除钱包、指纹 / Face ID 解锁。
2. 链：Arc（主链，gas 用 USDC）+ Ethereum、BSC、Base、Arbitrum、Polygon。所有 EVM 链共用一套助记词和地址（`m/44'/60'/0'/0/n`）。
3. 资产：总资产、代币列表（隐藏小额、搜索、手动添加代币）、收款二维码、转账（gas 慢 / 推荐 / 快 / 自定义）、交易记录。
4. Arm 全部功能：
   - 钱包内原生交易页（仿 Ave 代币详情 + 快捷买卖）：Arm 代币、$BOAT。
   - Arm 网站其余功能（发币、创作者领取、推广、快艇、游戏探索）在 DApp 浏览器里打开，靠注入的钱包接口工作。
5. DApp 浏览器：网址 / 搜索、推荐列表（先放 Arm 自己的页面）、最近浏览 / 收藏、打开前的风险提示、连接 / 签名 / 交易确认弹窗、菜单（收藏、复制链接、刷新、浏览器打开、分享）。
6. 设置：语言、货币单位、红涨绿跌、主题、指纹、节点（RPC）管理、关于。

**不做（第二版以后）**

- 非 EVM 链（Solana、Tron、比特币、TON、Sui）。
- 非 Arc 链上的兑换（聚合器）、跨链、合约交易、跟单、理财、NFT。
- WalletConnect 连接外部 DApp（Arm 网站已接好 `walletConnect` 连接器，钱包端要接 Reown WalletKit，要申请项目 ID）。
- 聊天里转账（心之音 IM 里发带金额的消息卡片，参考 Telegram Wallet）。
- 法币出入金。
- 多链资产的自动发现（要第三方数据接口，付费）。

## 3. 总体架构

```
心之音 App（Android Kotlin / iOS SwiftUI）
├─ 钱包入口（features.wallet 为真才显示）
├─ 钱包 WebView ──── https://wallet.arm.yyheart.com   ← 钱包界面，独立源
│     └─ JS 桥 ArmWalletNative：安全存储 / 生物识别 / 防截屏 / 扫码 / 分享 / 打开 DApp / 取票据
└─ DApp 浏览器 WebView ── 任意 https 网页（含 arm.yyheart.com）
      └─ 文档开始时注入 EIP-1193 + EIP-6963 钱包接口
            请求 → 原生 → 钱包 WebView（覆盖层）弹确认框 → 签名 → 结果回 DApp

Arm 后端（indexer）
├─ /api/wallet/session：核对心之音票据，决定钱包页可不可用
├─ 资产 / 价格 / 交易记录：Arc 用现有索引；其他链第一版只查原生币 + 默认代币表 + 用户添加的代币
└─ RPC 代理（可选）：多链 RPC 走服务器，避免公共节点限流、国内连不上

心之音后端（houduan）
├─ user.walletEnabled、sys_setting.wallet_global
├─ /user/me 返回 features.wallet
└─ POST /api/wallet/ticket：签发 5 分钟有效的票据给 Arm（非对称签名，Arm 只放公钥）
```

### 3.1 为什么钱包用独立源 `wallet.arm.yyheart.com`

Arm 主站有用户生成内容（代币名、简介、头像），万一哪里出 XSS，同源页面能读到同一个源的存储和内存。钱包放在独立子域：

- 同一个 Next.js 工程，按 Host 分流（Next 16 里中间件的写法以 `node_modules/next/dist/docs/` 为准，`AGENTS.md` 要求先读文档）。
- 钱包路由不加载任何第三方脚本，配严格 CSP（`script-src 'self'`、`connect-src` 只放 RPC / Arm API 白名单、`frame-ancestors 'none'`）。
- 电脑浏览器上，加密后的助记词存在这个源的 IndexedDB 里，跟主站隔离。

### 3.2 私钥怎么存

| 环境 | 存什么 | 存在哪 |
|---|---|---|
| App | 助记词用「钱包密码」派生的密钥（scrypt）做 AES-GCM 加密后的密文 | 原生安全存储：Android Keystore 加密的文件，iOS Keychain |
| App 指纹解锁 | 一把随机的「解锁密钥」，指纹 / Face ID 通过后才交给网页 | Android Keystore（`setUserAuthenticationRequired`），iOS Keychain（`biometryCurrentSet`） |
| 电脑浏览器 | 同样的密文 | 钱包源的 IndexedDB |

- 明文助记词只在解锁后的 JS 内存里；App 切到后台 5 分钟自动锁，锁定即清内存。
- 创建、导出助记词 / 私钥的页面调用桥接 `setSecureScreen(true)`：Android `FLAG_SECURE`，iOS 盖遮罩（Ave 也这么做，截图是空的）。
- 密码忘了只能用助记词重新导入（跟 Ave 一样，页面上写明）。
- 用 viem 自带的 `generateMnemonic` / `mnemonicToAccount` / `privateKeyToAccount`，不自己写密码学。

### 3.3 DApp 浏览器怎么接钱包

- Android：`androidx.webkit` 的 `WebViewCompat.addDocumentStartJavaScript` 注入 provider 脚本，用 `WebMessageListener` 收请求（只接受 https 页面）。iOS：`WKUserScript`（`atDocumentStart`）+ `WKScriptMessageHandler`。
- provider 同时挂 `window.ethereum` 并发 EIP-6963 公告（名字「心之音钱包」），Arm 的 wagmi 会自动出现这个连接器，Arm 网站基本不用改。
- 支持的方法：`eth_requestAccounts`、`eth_accounts`、`eth_chainId`、`wallet_switchEthereumChain`、`wallet_addEthereumChain`、`personal_sign`、`eth_signTypedData_v4`、`eth_sendTransaction`，其余读方法转发给当前链的 RPC。
- 每个站点单独授权（记住已连接的源）；签名 / 交易弹窗显示来源域名，并把常见调用翻译成人话：`approve`（标出无限授权）、Arm `LaunchFactory.launch`、路由 `exactInputSingle`、FeeLocker `claim`、BoatVault `buy / sell / claim / deposit`；不认识的显示原始数据和风险提示。
- 打开不在白名单里的站点前，先弹 Ave 那样的风险提示（第一版没有 AI 检测，只做白名单 + 提示）。

## 4. 开关

- 心之音数据库：`user.walletEnabled Boolean @default(false)`（照 `channelLimit` 的做法）；`sys_setting.wallet_global` = `off` / `per_user` / `all`，默认 `per_user`。
- 后台 `admin/src/views/UsersView.vue`：每行加「钱包」开关 + 批量开启；设置里放全局开关。
- 判断顺序：
  1. 原生壳：Android 是不是官网渠道包（构建时的渠道标记）；iOS 的 App Store 所在国家不是中国。不满足就整块不出现。
  2. `/user/me` 的 `features.wallet`（全局开关 + 用户开关）。
  3. 钱包页打开时拿票据找 Arm 后端核对（`/api/wallet/session`），防止直接输网址进入。
- **关掉开关只能隐藏入口，冻结不了用户的钱**（私钥在用户手上）。被关掉的用户如果已经建过钱包，还要能进「导出助记词 / 私钥」和「转出全部资产」页面。

在 Ave 上实测到的问题，我们要做得更好：

- **连接不确认**：选了网络和钱包后，Ave 直接把地址给了网页，没有弹「是否连接」。我们每个站点第一次连接都要确认，并记住授权，在设置里可以撤销。
- **签名框缺信息**：只有「钱包地址 + 签名内容 + 确认」，没显示请求来自哪个网站，也没有「拒绝」按钮（只能按返回键）。我们要显示来源域名和图标，加「拒绝」按钮，内容太长时可以展开。
- **取消后网页一直等**：按返回键关掉签名框后，Ave 没有回复拒绝，Arm 的「Sign in」按钮一直转圈（`a14-61-after-cancel`）。我们关掉任何弹窗都要回 EIP-1193 的 `4001 User rejected`。Arm 网站这边的签名 / 交易也要加超时或取消按钮（`components/boat/use-boat-account.ts` 等）。

**还缺的截图**：转账确认 / 输密码 / 结果页、DApp 交易确认弹窗、交易记录（这几页要钱包里有余额才弹得出来；需要的话给测试钱包 `uitest14` 转约 0.1 USDC）。

### 5.1 设计方向（比 Ave 好看）

Ave 的问题：信息很全但很挤，蓝白配色偏「工具」，到处是小字号和小标签，深色 / 浅色页面混着用（钱包页浅色、代币详情深色）。我们的方向：

- **跟 Arm 一个品牌**：沿用 Arm 的黑白灰（`globals.css`：浅色背景 `#f4f4f4`、卡片 `#ffffff`、主色 `#111111`；深色背景 `#000000`、卡片 `#0d0d0d`），涨跌色用 Arm 的 `--up #26a69a` / `--down #ef5350`。加一个品牌强调色只用在主按钮和总资产上（候选：Arm Logo 的银色渐变）。
- **深浅两套主题**，跟随系统；同一个页面里不混用。
- **层次少、留白多**：一屏只突出一件事（首页突出总资产，详情页突出价格和买入）；次要信息收进「更多」或者展开。
- **大圆角卡片**（Arm 的 `--radius: 1rem`）、轻阴影，不用 Ave 那种细边框表格。
- **数字用等宽字体**（Arm 已有 JetBrains Mono），小数位很多的价格用下标零（`0.0₄515`，Arm 已经这么显示）。
- **动效**：数字变化滚动、按下有回弹、底部弹窗手势下拉关闭、成功页有一个简短动画；全部 200 ms 左右，不拖沓。
- **安全相关页面单独一套严肃的样式**：助记词、导出私钥、签名确认用醒目的提示条和图标，风险高的操作（无限授权、未知合约）用红色并要求二次确认。
- 开工时先出 3～4 个关键页面（钱包首页、转账、代币详情 + 买入、签名确认）的静态稿，给操作者看过再铺开。

### 5.3 网页钱包核心（10.3，操作者看过设计稿后开工；未提交、未部署）

已接真实数据 / 真实签名：

- `lib/wallet/vault.ts`：助记词（viem `generateMnemonic` / `mnemonicToAccount`，路径 `m/44'/60'/0'/0/0`）和私钥导入；全部密钥用一个钱包密码加密（PBKDF2-SHA256 60 万次 → AES-GCM-256），只存密文 + 公开信息（名称、地址）。存储：App 壳注入 `window.ArmWalletNative.vaultGet / vaultSet / vaultClear` 就用原生安全存储，否则用 `localStorage["arm.wallet.vault.v1"]`。加钱包复用已解锁的密钥；导出 / 删除每次重新验密码。
- `components/wallet/wallet-context.tsx`：状态（空 / 锁定 / 已解锁）、多钱包切换 / 改名 / 删除、当前链；刷新页面即锁定，切到后台 5 分钟自动锁定；明文只在内存。
- `lib/wallet/chains.ts`：Arc + Ethereum / BNB Chain / Base / Arbitrum / Polygon（公共 RPC，各链默认 USDC / USDT 地址）；Arc 的链定义里没有 Multicall3，所以只对有的链开批量读。
- `lib/wallet/assets.ts`：Arc 用 indexer `/api/wallet/:address`（USDC + Arm 代币持仓）+ 链上读 BOAT 余额（价格用 `/api/boat/info`）；其它链读原生币 + 默认稳定币，原生币价格用 CoinGecko 公共接口（拿不到就显示「—」）。

### 5.5 DApp 浏览器 + iOS 壳（10.3 下午；网页已部署，Android / iOS 待操作者编译）

- **结构**：钱包和 DApp 在同一个原生页面里。钱包 WebView（背景透明）在下，DApp WebView 在上；DApp 发来要确认的请求时钱包页弹底部确认框并调 `dappShow(true)`，原生把钱包 WebView 提到最上面，钱包页给 `<html>` 加 `wallet-overlay`（背景透明）、主内容 `invisible`，确认框后面露出的是 DApp 网页。私钥一直只在钱包 WebView 的内存里，解锁一次钱包和 DApp 共用。

### 5.6 扫一扫 + 节点页 + DApp 连不上钱包的修复（10.3 晚；网页已部署，Android / iOS 待操作者编译）

## 7. 风险和要先解决的问题

1. **老 WebView 打不开 Arm 网站（10.3 实测）**：雷电模拟器（Android 9，系统 WebView 是 Chromium 91）里用 Ave 的 DApp 浏览器打开 arm.yyheart.com，样式全丢，只剩裸 HTML（截图 `31-dapp-arm-loaded`）；同一个 Ave 在 Android 14（WebView 146）上显示正常（`a14-31-arm-loaded`）。原因：Tailwind v4 要求 Chrome 111+ / Safari 16.4+，Chromium 91 不支持 `@layer` 等语法，整份样式表失效。没有谷歌服务的国产机 WebView 可能不更新，钱包页和 DApp 浏览器都受影响。处理方案（操作者 10.3 定）：不统计、不降级 CSS，只在原生壳里兜底——打开钱包 / DApp 浏览器前读 WebView 主版本（Android `WebView.getCurrentWebViewPackage()`），低于 111 就提示升级「Android System WebView」并给出应用商店链接。以后真有用户反馈再考虑 CSS 降级。**10.3 更新**：华为等厂商 WebView 常停在 Chromium 99，钱包页已做 99 兼容，门槛降到 99；内核版本改从 UA 取。**10.3 晚改成全站兼容**（操作者在华为上用 DApp 浏览器打开 Arm，钱包选择框跑到右下角、按钮成了黑条）：`src/app/compat.css` 由 `scripts/compat-css.mjs` 从**构建后的 CSS** 生成，根布局加载，把 `color-mix(…, transparent)` 换成 rgb() 带透明度（否则 Tailwind 退回不透明色）、`translate` / `scale` / `rotate` 属性换成 `transform`（Dialog 居中靠它）、Tailwind 的 filter 链（Chromium 99 算出来是 `none`）写成具体的 `blur()` 等、dvh 换成 vh；全部包在 `@supports not (...)` 里，iOS 和新内核不受影响。加了半透明颜色类或 translate / scale / rotate 后要重新生成：`npx next build && node scripts/compat-css.mjs`，再构建一次。容器单位（cqw，Chromium 105+）没法通用转换，首页按钮字号在 `globals.css` 里单独兜底。仍然别用 `:has()`。
2. **iOS 审核**：「默认关闭 + 后台开」可能被认为是隐藏功能（审核规则 2.3.1）。给审核账号打开钱包，并在备注里写明是灰度功能。
3. **私钥丢失**：自托管的代价，强制备份校验，页面写清风险。
4. **公共 RPC**：国内访问部分节点不稳定（`web3.ts` 里已经记过 Arcscan 节点的问题）。考虑走 Arm 服务器做 RPC 代理。
5. **签名弹窗的「人话」解析**：解析错了会误导用户。不认识的调用一律显示原始数据 + 警告，不猜。
